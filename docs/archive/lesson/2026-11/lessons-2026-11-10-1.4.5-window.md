# Session Findings - 1.4.5 Window

Durable lessons recorded when a session ends.

Each entry names a wound, its root cause, and the rule that now prevents it.

Entries use titles, never ordinal numbers - unnumbered entries reorder freely.

The appendix indexes rules that live in the owning document's body - it does not hold rules.

If no existing rule covers a lesson, add the rule to the owning document first, then index it here.

### Scoped overrides clear advisories a force-fix cannot

Observed symptom: `npm audit` reported 15 moderate `minimatch` advisories and offered only `npm audit fix --force`, which downgrades eslint 10 to 9 - a breaking regression against the eslint-10 migration.

Root cause: the five flagged parent chains (`eslint`, `@eslint/config-array`, `@typescript-eslint/typescript-estree`, `@electron/universal`, `app-builder-lib`) cap `minimatch` at `^10.2.2` while the patched release line is 11.0.1+ - no parent upgrade inside declared ranges can reach it.

Preventing rule: see "Scoped overrides pin the fix when parents cap the range" in `WORKFLOW.md`.

### Suite reads during parallel delegation can catch mid-write files

Observed symptom: a full `npm test` run reported one failing file while a delegated change was actively writing its new test file; the next run passed 792/792.

Root cause: the orchestrator ran the suite against the live tree mid-write, so the failure was a transient read, not a regression.

Preventing rule: see "Context Management" in `WORKFLOW.md` - suite runs wait for delegated writes to land.

### A record can enter the window's group mid-run

Observed symptom: the release gate counted 9 records under `docs/change/1.4.5/` while the intake catalogue held 8; the ninth record (`js-output-layout`) then sat under `docs/change/1.4.6/` with its plan at review time.

Root cause: the change group is a live directory - the host and audit triage can file or relocate records while the window runs, and an intake snapshot goes stale.

Preventing rule: see "Run State" in `WORKFLOW.md` - re-enumerate the change group at review time; late records defer to the next window unless explicitly added.

### Consolidate repeated semantics during planning, not after

Observed symptom: the accessibility record stamped `role="dialog"`/`aria-modal`/`aria-label` on 13 modals individually, and the window's own refactoring cycle then had to extract the identical frame into `DialogFrame` - the same surface edited twice in one window.

Root cause: the record's implementation chose per-file semantics before checking whether a shared abstraction had crossed the Rule-of-Three threshold; the refactoring phase paid the consolidation cost.

Preventing rule: covered by "Apply the Rule of Three" in `REFACTORING.md` - the threshold was met 13 times over at implementation time. When a record stamps the same semantics on many sites, evaluate the shared wrapper during planning, not only in the refactoring phase.
